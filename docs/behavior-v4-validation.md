# 評分與上下文 v4.1

2026-11-09。本次完成程式與覆核流程；Qwen3.5 4B 的語意驗收未全數通過，未啟動真實資料全量分析。

## 使用

重新整理網頁，開啟已存資料及模型設定，選「開始新分析」套用 `behavior-evidence-v4.1`／`eight-dimensions-v2`。原紀錄仍使用原提示詞，不會自動重算或混入新統計。開發期間建立的早期 v4 紀錄只供查看及覆核，不能以新的契約續跑。

進度面板的「待覆核」及成員頁同名分頁可檢查未納入統計的訊息。「全部訊息」可重新查看零分與已覆核訊息。覆核頁包含逐維理由、本人／引用／上下文證據、模型兩輪原值及實際模型輸入。人工修正保留模型結果，立即重新計算有效分母。

## 上下文如何取得

- 保留原本批次前 20／後 10 則、兩側各 30 分鐘的鄰近訊息及兩層精準回覆祖先。
- 使用穩定 ID 建立 @／回覆關係索引。只有唯一對應的 QQ 號碼才解析為成員，不以名字猜配。
- 加入目標在 48 小時內最多 4 則精準後續回覆。
- 每則目標最多查 3 個明確對象的雙向互動。一般回查 2 小時；「昨晚、之前、仍在追問」等時間／延續線索回查 48 小時。這些線索只控制取資料，不決定分數。
- 每對互動最多掃描最近 200 則，按 30 分鐘間隔分段，取最近 4 段的開頭、結尾與最近發言，最多 16 個候選，再補候選前後各 1 則、限 2 分鐘的鄰近訊息。
- 歷史資料標示為候選，不能直接當作同一事件。每條精準祖先及候選保留對應的目標 ID，引用內容與本人文字分開編號。
- 容量不足先縮小批次，再移除普通鄰居、候選鄰居、較遠候選；保留精準祖先與後續回覆。刪減及缺失會記錄。仍放不下則標容量不足，不截斷目標文字。

這是有上限的關係檢索，不是完整話題重建。未指名、沒有 reply ID、超過回查範圍的事件仍可能漏掉；候選關係也不等於已證明同一話題。

## 評分與覆查

模型先解釋本句承接的事件，再判話語行為及對象，最後獨立給八維分數。每個正分／未知維度須有理由；零分可附反證。正分須引用本人原文，隱含挑釁與升級另須引用有關聯的其他發言。

攻擊／挑釁／升級正分、完整跨時段互動及可修正的結構矛盾，最多再做一次反證覆查；缺失圖片或事件不靠重複推理補造。兩輪有害維度的數值不同、第二輪失敗、引用歸屬錯誤、判讀與分數矛盾或重要資訊不足，整則標為待覆核，所有維度暫不進排行榜。這個排除方式會降低覆蓋率，不能把剩餘樣本當成全體的無偏估計。

引用編號、結構關係及幾種矛盾可以由程式檢查；理由是否真正符合語意仍需模型及人工判斷。兩輪同樣判錯仍可能通過，不宣稱是語意正確性的保證。

批次輸入只保存一份；逐則結果以 batch ID 連結。API Key 不進入快照。兩輪 token 均計入用量，費用上限預留兩輪與最多重試的用量。六路排程保持原有空位即補的方式。

模型為當前 `local-model`（Qwen3.5 4B Q4 GGUF），llama.cpp `http://127.0.0.1:8080/v1`，16K 上下文、輸出 2048、temperature 0、關閉思考；工作器驗收採六路。Ollama／vLLM 本次未實跑新版契約。

20 個案例包含開發與保留組，預期範圍在執行前固定。開發過程曾看過保留組結果，因此最終 14／20 是回歸結果，不是獨立泛化評估或真實資料準確率。未符合者包括缺圖時以 0 代替 null、制止辱罵的建設性、友善釐清、辱罵兼挑釁的邊界、諷刺及動員衝突強度。原始失敗結果保留在 `.data/behavior-calibration-*`，未修改標準使測試轉綠。

真實回放中，「我媽是」、自述慣用髒話、養貓縮寫與水群玩笑的有害分數有改善；自嘲仍曾被誤讀。長事件的兩則相同反問取回了數小時前的點名追問：其中一則判挑釁 2，另一則仍判 0，兩者均因事件不完整／矛盾而保留覆核。這表示仍未解決所有漏判。兩次開發回放分別有 4／8 則輸出驗證失敗；當時尚不接受零分反證，後續已調整為保留有效零分說明，但不能把早期失敗記錄算成通過。

單則對抗案例與額外覆查比原批次協定慢；本次沒有取得新的全量速度數字，不能沿用舊版 1–2 小時的預估。人工標註、完整時間範圍代表性與全量速度仍待驗證。

## 重現與人工校準

```powershell
node scripts/calibrate-behavior.js --url http://127.0.0.1:8080/v1 --model local-model --out .data/behavior-calibration-new
node scripts/sample-corpus.js C:/path/to/exported-results.jsonl .data/behavior-review-300.jsonl
npm test
npm run build
npm run verify:pages
```

校準程式使用已固定的合成案例，只在明確執行時呼叫指定服務；任何不符合預期的案例使程式以非零狀態結束。抽樣程式不呼叫模型，從本工具的逐則 JSONL 依月份、發言量與訊息類型分層，固定種子選 300 則並保留上下文與待填人工分數。

本機已產生 300 個不重複樣本，涵蓋來源中的 14 個有資料月份、189 個分層，69 則標記保留組；尚未人工標註。原始聊天、抽樣、模型回覆與 UI 截圖都保存在忽略的 `.data/`、`output/`，不進 GitHub Pages 資產。
